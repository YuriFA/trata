# Refactor: слой дат на date-fns v4 в новом пакете `packages/dates`

## Решения (подтверждены пользователем)
- Библиотека: **date-fns v4** — чистые функции над нативным `Date`, ru-локаль как данные в пакете (без опоры на Intl на Hermes, в духе money-пакета), tree-shak'ается Metro (ESM, Expo 54).
- Устройство: **новый workspace-пакет `@trata/dates`** поверх date-fns; mobile переводится сейчас, web не трогаем (у него чистый слой над `@internationalized/date`, связанный с reka-ui; миграция — отдельное будущее изменение).
- Видимая строка вывода не меняется: текущие подписи закреплены тестами (`format.test.ts`, `selectors.test.ts` и др.).

## Контекст (из исследования)
В mobile ноль date-библиотек. Ручной код: 4 массива RU-месяцев (`format.ts:22-82`), WEEKDAYS (`date-picker-sheet.tsx:15`), трюк `new Date(y, m+1, 0)` ×3, «понедельник = `(getDay()+6)%7`», `padStart`-ключи `yyyy-MM-dd` ×2, полночная арифметика `calendarDaysAgo`, ручной RU-плюрализм `daysAgoLabel`, дубли «Сегодня/Вчера» (`quick-dates.ts:17` + `format.ts:112`), дубль месяц-навигации (`calendar/month.ts` vs `shiftMonth` в date-picker-sheet).

## 1. Каркас пакета `packages/dates`
По образцу `packages/money`/`packages/i18n`:
- `package.json`: `@trata/dates`, 0.0.0, private, type module, source-exports `./src/index.ts` (types+import), dependency `date-fns@^4`, скрипты `type-check` (+ vitest по образцу money).
- `tsconfig.json`: ESNext, `moduleResolution: bundler`, strict, noEmit, `include: ["src"]`.
- Чистый TS без DOM/RN API — соответствует правилам `packages/*` (AGENTS.md). date-fns объявляется **только** здесь; mobile не импортирует date-fns напрямую, только фасад пакета.
- `pnpm install`; добавить `@trata/dates: workspace:*` в deps apps/mobile.

## 2. API пакета (сохраняем сигнатуры mobile, чтобы дифф был механическим)
Локаль — строкой, как в `formatMoney(amount, currency, locale)`: внутри резолвится в `Locale` из `date-fns/locale` (ru → `ru`, иначе `enUS`), по умолчанию `'ru'` (текущая реальность mobile; TODO(i18n) переносится в шапку пакета).

- `labels.ts`:
  - `monthRangeLabel(year, month, {locale})` → `"1 АВГ. — 31 АВГ."` — композить одним `format(newDate(y, m, 1), 'd MMM')` + `toUpperCase()` (числовой контекст даёт родительный падеж, «МАЯ» остаётся корректным);
  - `monthRangeLabelShort(...)` → `"1 авг. - 31 авг."`;
  - `fullDayLabel(date | occurredAt, {locale})` → `format(d, 'd MMMM')` → `"17 августа"`;
  - `relativeDayLabel(date, {now, locale})` → сегодня/вчера/`"14 АВГ."`;
  - `daysAgoLabel(days, {locale})` → `formatDistance(subDays(now, days), now, {locale, addSuffix: true})` → `"2 дня назад"` (плюрализм из ru-локали);
  - константы today/yesterday (ru/en) — один источник вместо двух дублей; помечены TODO(i18n) → в бандлы `@trata/i18n`, когда mobile подключит react-i18next.
- `month.ts`: `MonthCursor {year, month}` + `currentMonth/previousMonth/nextMonth` (через `newDate` + `addMonths`), `isCurrentOrFutureMonth`, `transactionsInMonth<T extends {occurredAt: string}>` (generic по образцу money — без зависимости от `@trata/api`), `monthLabel(year, month)` → `"Август"` (`'LLLL'`, именительный).
- `grid.ts`: `monthGrid(year, month): (number | null)[][]` (из `startOfMonth`/`getDaysInMonth`/`startOfWeek(d, {weekStartsOn: 1})` + чанки по 7), `weekdayLabels({locale})` → `['ПН', …]` (`eachDayOfInterval` + `'EEEEEE'` + uppercase).
- `keys.ts`: `calendarDayKey(date)` → `format(d, 'yyyy-MM-dd')`; `nowIso()` → `new Date().toISOString()`.
- `index.ts` — публичный фасад.
- Тесты пакета: закрепить все текущие строковые выходы (включая високосный год,timezone-стабильные фикстуры полдня-UTC как в `format.test.ts:20-23`).

2. `shared/lib/format/format.ts`: оставить только `DEFAULT_CURRENCY` + `formatAmount`; все date-функции удаляются (переход на пакет).

## 4. Web
Без изменений. Пакет спроектирован так, чтобы web позже мог перенести свой чистый строковый слой (`currentDay`, `parseCalendarDay`, `addCalendarDays`, границы дня, `nowIsoString`) на `@trata/dates`, оставив reka-ui-адаптер web-локальным. Расхождение семантик границ дня (web local / mobile UTC) при этом придётся сводить — не в этом изменении.

## Риски
- Точная типографика ru-аббревиатур date-fns может отличаться от текущих массивов (напр. формы мая). Стратегия: композить подписи одним `format()` + `toUpperCase()` (грамматика падежей сохраняется); если тест зафиксирует отличие — принять каноническую форму date-fns и обновить тест, отметив визуальную дельту в отчёте.
- `pnpm knip` может пожаловаться на неиспользуемые экспорты — держим API минимальным (только потребляемое mobile).
